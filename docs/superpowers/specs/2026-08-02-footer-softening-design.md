# A2 页尾弱化设计稿

日期：2026-08-02

## 目标

这次调整同时解决两个问题：

1. 操作按钮的文案更准确，避免“功能动作”和“结果分享”混在一起。
2. 页尾不再像一个独立功能卡片，而是更像页面的自然收尾；普通用户能感知“本页到这里结束”，愿意继续了解的人也能找到 GitHub 和反馈入口。

## 本次包含的改动

### 1. 按钮文案统一调整

- `重置` -> `参数重置`
- `生成图片` -> `图片分享`
- `复制结果` -> `文字分享`

这 3 处文案需要在桌面与移动端保持一致，并同步影响桌面重排脚本里的按钮文本覆盖逻辑。

### 2. 页尾从“卡片区块”改为“收尾注脚”

当前页尾的问题不是信息太多，而是视觉重心太强：白底、边框、圆角、三栏结构和按钮式链接，会让用户误以为这里还有一块功能区。

新的 A2 方向改为：

- 页尾保留在主内容宽度体系内，与上方内容对齐
- 取消“大白卡”感，弱化边框、圆角、背景存在感
- 用一条淡分隔线 + 一句结束提示，明确传达“这一页到这里结束”
- 深入链接降级成低强调文本链接，而不是按钮
- 保留版权与免责声明，但退到最低视觉层级

## 建议的页尾信息结构

从上到下改成 4 层：

1. 结束分隔线
2. 结束提示：`本页内容到这里结束`
3. 辅助说明：`如需继续对比，可回到上方调整参数。`
4. 深入入口：`继续了解：项目源码 / 提交反馈`
5. 最弱一层元信息：`© 2026 cost.ahopig.com · 结果仅供估算，不构成购车、投资或理财建议。`

这里的关键不是加信息，而是重新排序：先让用户明确“结束”，再让少数想继续了解的人看到入口。

## 视觉表现

### 桌面端

- 页尾整体不再使用高存在感卡片样式
- 主要靠顶部细分隔线和较大的上留白形成“收尾”感
- 文字整体降噪：
  - 结束提示用中等字重
  - 辅助说明和深入入口用更浅的灰色
  - 版权与免责声明最浅
- `项目源码` 与 `提交反馈` 改成普通文本链接或极轻的 inline 链接，不再保留胶囊按钮感
- 维持与 `.wrap` 一致的桌面最大宽度，避免再次出现“下方另起一块”的体感

### 移动端

- 改成单列、居中或偏居中排布
- 优先显示“结束提示”，让用户一眼知道这是页尾而不是功能面板
- 深入入口放在结束提示下方，使用小号文本链接
- 收紧上下 padding，避免在小屏里占据过强视觉面积
- 不再出现明显像按钮的源码/反馈入口

## 交互与行为

本次不新增任何功能行为，只做信息层级和文案优化：

- GitHub 源码与反馈链接仍然保留原目标地址
- 分享/重置按钮逻辑不变，只修改显示文本
- 现有统计埋点逻辑继续沿用；如果埋点通过 `.footer-link` 识别反馈点击，需要确保新的轻链接仍保留兼容选择器或同步更新选择器

## 代码层面预期改动

主要会落在以下区域：

- `index.html`
  - 顶部/底部按钮文案
  - 桌面重排脚本中的按钮文本覆盖
  - 页尾 HTML 结构
  - 页尾 CSS
  - 如有必要，页尾链接相关的埋点选择器
- `tests/footer.test.js`
  - 从“页尾卡片布局”断言调整为“收尾注脚”断言
  - 继续覆盖宽度对齐规则
- 如有需要，补一个按钮文案回归测试，避免桌面脚本把新文案覆盖回旧文案

## 验收标准

改完后应满足：

1. 用户滚到底部时，第一感受是“内容结束了”，不是“还有一个功能区”。
2. 桌面端页尾与上方主内容使用同一套宽度体系。
3. 移动端页尾明显比现在更轻，不再像一张独立卡片。
4. `参数重置 / 图片分享 / 文字分享` 在桌面和移动端都一致可见。
5. GitHub 源码与反馈入口仍可正常访问。
6. 与本次修改直接相关的回归测试通过。
